# AI Monster Workflow — Глубокий анализ кода, исправление багов, оптимизация и непрерывное улучшение

## Назначение

Этот workflow превращает ИИ-ассистента в "монстра" разработки, который:
- Глубоко анализирует весь код проекта
- Находит 20-50 багов за сессию
- Предлагает 5 вариантов исправления для каждого бага
- Оптимизирует алгоритмы и структуры данных
- Использует CUDA/GPU там где нужно
- Пишет тесты
- Думает о нагрузке, распределении, защите от хакеров и утечек
- Предлагает улучшения и записывает их в docs/future_development.md
- Обновляет CHANGELOG.md
- Обновляет README_PROJECT_OVERVIEW.md
- Коммитит изменения

## ПРИНЦИПЫ

1. **Глубокий анализ** — читать весь файл, не спешить, понимать контекст
2. **Без over-engineering** — использовать продвинутые концепции, но не усложнять без причины
3. **5 вариантов исправления** — для каждого бага предлагать минимум 5 способов фикс
4. **Производительность** — всегда думать о скорости, памяти, кэшировании
5. **Безопасность** — проверять на инъекции, утечки, уязвимости
6. **Тестирование** — писать тесты для всего
7. **Документация** — обновлять docs, CHANGELOG, README
8. **Коммиты** — коммитить после каждого значительного изменения

### Шаг 3: Поиск багов и проблем

**Действие:**
- Найти баги и проблемы в файле
- Минимум 20-50 багов за сессию

**Типы багов для поиска:**

1. **Логические ошибки**
   - Неверные условия
   - Неверные операторы
   - Неверный порядок операций
   - Off-by-one ошибки
   - Null pointer dereferences
   - Uninitialized variables

2. **Ошибки обработки ошибок**
   - Отсутствие try-catch
   - Неверная обработка исключений
   - Игнорирование ошибок
   - Неверные коды ошибок

3. **Проблемы производительности**
   - N^2 алгоритмы там где можно O(n log n)
   - Неверные структуры данных
   - Избыточные копирования
   - Отсутствие кэширования
   - Неверное использование памяти
   - Отсутствие SIMD/GPU

4. **Проблемы безопасности**
   - SQL injection
   - XSS
   - CSRF
   - Hardcoded secrets
   - Неверная валидация
   - Race conditions
   - Deadlocks

5. **Проблемы архитектуры**
   - Нарушение SOLID
   - God classes
   - Circular dependencies
   - Tight coupling
   - Неверное разделение ответственности

6. **Проблемы кода**
   - Дублирование
   - Сложные условия
   - Магические числа
   - Длинные функции
   - Глубокая вложенность
   - Плохие имена

### Шаг 6: Оптимизация алгоритмов и структур данных

**Действие:**
- Проверить все алгоритмы в файле
- Если можно оптимизировать — оптимизировать

**Оптимизации для проверки:**

1. **Сложность алгоритмов**
   - O(n^2) → O(n log n) или O(n)
   - Рекурсия → итерация
   - Вложенные циклы → один цикл

2. **Структуры данных**
   - List → Set/Dict для поиска
   - List → Deque для очереди
   - Dict → OrderedDict если важен порядок
   - Array → numpy array для чисел

3. **Кэширование**
   - Добавить lru_cache
   - Добавить memoization
   - Кэшировать дорогостоящие вычисления

4. **Параллелизм**
   - asyncio.gather для параллельных I/O
   - ThreadPoolExecutor для CPU-bound
   - multiprocessing для тяжёлых задач

5. **SIMD/GPU**
   - Использовать numpy vectorization
   - Использовать numba
   - Использовать CUDA для C++
   - Использовать SIMD intrinsics

### Шаг 7: Использование CUDA/GPU где нужно

**Действие:**
- Проверить есть ли вычисления которые можно ускорить на GPU
- Если да — добавить CUDA/GPU код

**Кандидаты для GPU:**
- Матричные операции
- Машинное обучение
- Monte Carlo симуляции
- Обработка изображений
- Криптография
- Финансовые расчёты

**Пример:**
```cpp
// CPU версия
void calculate_rsi(const float* closes, float* rsi, int n, int period) {
    for (int i = period; i < n; ++i) {
        // RSI calculation
    }
}

// GPU версия
__global__ void rsi_kernel(float* closes, float* rsi, int n, int period) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        // RSI calculation on GPU
    }
}
```

## ПРИМЕР РАБОТЫ

### Пример 1: Нахождение и исправление бага

**Файл:** `ai-signal-bot/src/strategies/trend_following.py`

**Анализ:**
- Читаю файл
- Нахожу баг: RSI рассчитывается неправильно (используется SMA вместо EMA)

**5 вариантов исправления:**

Вариант 1: Исправить формулу RSI
- Плюсы: Просто, быстро
- Минусы: Может повлиять на другие части
- Сложность: Низкая
- Риск: Средний

Вариант 2: Использовать библиотеку ta-lib
- Плюсы: Надёжно, протестировано
- Минусы: Новая зависимость
- Сложность: Низкая
- Риск: Низкий

Вариант 3: Добавить параметр для выбора типа MA
- Плюсы: Гибкость
- Минусы: Сложнее API
- Сложность: Средняя
- Риск: Низкий

Вариант 4: Использовать EMA из numpy
- Плюсы: Нет новых зависимостей
- Минусы: Нужно реализовать EMA
- Сложность: Средняя
- Риск: Средний

Вариант 5: Переписать весь индикатор с нуля
- Плюсы: Полный контроль
- Минусы: Долго, много работы
- Сложность: Высокая
- Риск: Высокий

**Выбор:** Вариант 1 (исправить формулу)

**Исправление:**
```python
# Было:
avg_gain = sma(gains, period)
avg_loss = sma(losses, period)

# Стало:
avg_gain = ema(gains, period)
avg_loss = ema(losses, period)
```

**Тест:**
```python
def test_rsi_with_ema():
    """Test RSI calculation with EMA."""
    prices = [...]
    rsi = calculate_rsi(prices, period=14)
    assert 0 <= rsi <= 100
```

**Коммит:**
```
fix: correct RSI calculation to use EMA instead of SMA

RSI was incorrectly using SMA for average gain/loss calculation.
Changed to EMA to match standard RSI formula.

Fixes: #123
```

### Пример 2: Оптимизация алгоритма

**Файл:** `hft-trade-bot/src/strategies/signal_engine_v2.cpp`

**Анализ:**
- Читаю файл
- Нахожу: O(n^2) алгоритм для поиска символа в списке

**Оптимизация:**
```cpp
// Было: O(n) поиск в векторе
for (const auto& symbol : symbols) {
    if (symbol == target) {
        // ...
    }
}

// Стало: O(1) поиск в unordered_set
if (symbol_set.find(target) != symbol_set.end()) {
    // ...
}
```

**Тест:**
```cpp
TEST(SignalEngineV2, SymbolLookupPerformance) {
    // Test that lookup is O(1)
}
```

**Коммит:**
```
perf: optimize symbol lookup from O(n) to O(1) using unordered_set

Symbol lookup was using linear search in vector.
Changed to unordered_set for O(1) average case lookup.

Performance improvement: ~100x for large symbol lists.
```
